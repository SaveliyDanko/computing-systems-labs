# Лабораторная 3 — таймеры, вариант 1 «Музыкальная клавиатура»

Самостоятельный проект STM32CubeIDE для **SDK-1.1MC.427 / STM32F427**.
Назначенный номер — **6**. По подтверждённому правилу циклического выбора
из пяти заданий `(6 - 1) % 5 + 1 = 1`, поэтому реализован **вариант 1**,
как в ЛР 1 и 2. Требования сверены с заметкой Obsidian
«Лабораторная работа 3» и разделом 5.3, печатные страницы 82–84,
[пособия SDK-1.1M, редакция 23.09.2026](https://docs.yandex.ru/docs/view?url=ya-disk-public%3A%2F%2FgnZjE%2B0%2BtAOnWD%2BQF6x%2FKHumUuwVPt0puaIMSPgwP2pdqinF8TVHBZsJz%2BlCybhSq%2FJ6bpmRyOJonT3VoXnDag%3D%3D&name=SDK-1.1M_26092301.pdf&nosw=1).
В пособии раздел помечен «задание уточняется»; здесь реализовано именно это условие.

## Подключение и запуск

1. Подключить питание стенда и **DBG USB**. BOOT0 — загрузка из Flash.
2. **Замкнуть SA2.7**: этот переключатель соединяет сигнал таймера с усилителем
   звукоизлучателя BA1. SA2.8 для воспроизведения не требуется.
3. Собрать и прошить программу командами ниже.
4. Открыть UART-канал FT2232 (**Interface 1**) в терминале:
   **57600 бит/с, 8N1, без flow control**, кодировка **UTF-8**, local echo выключен.
   Клавиши должны отправляться сразу: в PuTTY отключить **Local line editing**.
   Для Enter подходят CR, LF и CRLF.
5. После сброса звук выключен, выбрана первая октава **5/9**, длительность **1,0 с**.

FT2232 **Interface 0** используется OpenOCD/JTAG, Interface 1 — COM-портом.
В Windows WinUSB устанавливается только для Interface 0; для Interface 1 нужен
FTDI VCP. Не менять драйвер UART-интерфейса на WinUSB.

По [электрической схеме](docs/SDK1.1M.pdf), страницы PDF 2–4 и 7:
**PA5, AF1, TIM2_CH1 → ADC/TIM.CH1 → SA2.7 → DA1.2 → BA1**.
Имя сети `T1_CH1/A5` на схеме не означает TIM1: на STM32F427 PA5/AF1 соответствует
TIM2_CH1. UART использует **USART1, PA9/PA10, AF7**; общие линии PC6/PC7
оставлены входами. Контакты JTAG не перенастраиваются.

## Управление

| Клавиша | Действие |
|---|---|
| `1`–`7` | До, ре, ми, фа, соль, ля, си выбранной октавы |
| `+` / `-` | Увеличить / уменьшить октаву в пределах 1–9 |
| `A` / `a` | Увеличить / уменьшить длительность на 0,1 с; пределы 0,1–5 с |
| Enter | Семь нот выбранной октавы подряд, без заданных пауз |
| Другой символ | `ERROR: неверный символ, код 0xXX` |

Октавы по порядку: субконтроктава, контроктава, большая, малая, первая, вторая,
третья, четвёртая, пятая. В UART их имена выводятся латиницей:
`subcontra`, `contra`, `great`, `small`, `first`, `second`, `third`, `fourth`, `fifth`.
Каждая нота сопровождается сообщением с названием, октавой, частотой и длительностью;
настройка — новыми значениями октавы и длительности. На границе диапазона
настройка сохраняется и выводится `LIMIT`. Эхо и ответы не требуют Enter.

Принятая политика для случаев, не определённых заданием:

- Новая нота или Enter сразу заменяет текущее воспроизведение.
- Изменение октавы/длительности действует на следующий запуск; уже запущенная
  нота или вся гамма сохраняет исходные настройки.
- CRLF запускает одну гамму; отдельные CR и LF также поддерживаются.
- Гамма продолжается независимо от входа и отправки UART. Пропущенное время
  при задержке главного цикла не удлиняет её: автомат пропускает истёкшие ноты.

## Сборка и прошивка

Из корня репозитория (в Windows допустима команда `python` вместо `python3`):

```bash
python3 lab3/tools/build.py
python3 lab3/tools/board.py flash
```

Сборка создаёт `lab3/build/lab3.elf` и `lab3/build/lab3.bin`.
Нужны Python 3 и `arm-none-eabi-gcc` в PATH либо `ARM_GCC_BIN` с каталогом
toolchain. В Windows поддерживается поиск CubeIDE в `C:/ST`.
Для прошивки задать `OPENOCD_EXE` и `OPENOCD_SCRIPTS` (каталог с
`target/stm32f4x.cfg`). Используется локальный `SDK11M.cfg`, **FT2232/JTAG**.
Команды `probe` и `debug` проверяют доступ и запускают GDB-сервер соответственно.

В CubeIDE импортировать каталог `lab3` как **Existing Project**, без копирования.
Debug/Release создают `Debug/lab3.elf` / `Release/lab3.elf`. Для их прошивки:
`python3 lab3/tools/board.py flash --elf lab3/Debug/lab3.elf`.
Для отладки использовать пользовательский OpenOCD/JTAG config `SDK11M.cfg`.
CubeMX и `.ioc` не требуются; часы, UART и таймер настроены вручную.

## Архитектура и частоты

Из ЛР 2 сохранены GPIO-драйвер, HAL UART-адаптер и очереди `serial`.
Драйвер UART работает с прерываниями; переключать режим для этой работы не нужно.
`piano` — независимый от аппаратуры автомат, `console` обрабатывает отдельные
символы, `sound` управляет аппаратным PWM TIM2, `clock` задаёт частоты.
Главный цикл не содержит задержек, ожидания конца ноты или опустошения UART.

HSI 16 МГц → PLL M=8, N=120, P=2, Q=5 → **ядро 120 МГц**.
AHB /1, APB1 /4 = 30 МГц, APB2 /2 = 60 МГц; TIMPRE=0,
**TIM2CLK=60 МГц**, PSC=0. Для частоты ноты `f`:

```text
N = round(60 000 000 / f)
ARR = N - 1
CCR1 = floor(N / 2)
f_actual = 60 000 000 / N
```

32-разрядный TIM2 охватывает все девять октав без смены предделителя.
Частоты равномерно темперированного строя хранятся в целых миллигерцах,
Ля первой октавы = 440 Гц. Для неё ARR=136363, CCR1=68182.
Длительности отсчитываются по SysTick 1 мс, переполнение `uint32_t` учтено.
Остановка устанавливает CCR1=0, поэтому выход удерживается низким.
Подробные формулы и вопросы для защиты: [DEFENSE.md](docs/DEFENSE.md).

RX/TX-очереди — 128/512 байт, размеры меняются макросами в `serial.h`.
Консоль резервирует место под эхо и целый ответ. При потере входа из-за ошибки
UART или переполнения выдаётся `ERROR: input lost; repeat the last key`.
Без flow control неограниченный поток не гарантируется; ориентироваться на ответы
терминала. UART API рассчитан на один main и один USART1 ISR, без RTOS.

## Проверки

```bash
python3 -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r lab3/tests/requirements.txt
python lab3/tools/build.py
python lab3/tools/build.py --test
python lab3/tests/run_tests.py
```

Тесты исполняют настоящий Cortex-M4 C-код в Unicorn, проверяют автомат,
все частоты, регистры PWM, часы, UART и запуск готовой прошивки от Reset_Handler.
Модель проверяет MMIO и логику; звучание, реальные частоты HSI, USB и COM-порт
проверяются на стенде. Результаты и сценарий: [VALIDATION.md](docs/VALIDATION.md).
Сторонние компоненты и лицензии: [THIRD_PARTY.md](docs/THIRD_PARTY.md).
