# Пояснения к защите лабораторной 2

## Что реализовано

Вариант 1 развивает светофор из ЛР 1. Часть 1 использует HAL UART и поддерживает
опрос/прерывания в одном приложении; часть 2 — отдельная прошивка с собственным
UART без вызовов HAL/LL UART. Выбор делается символом `UART_REGISTER_BACKEND`,
а переключение I/P — командой во время работы. Требования к командам и единицы
X сверены с разделом 5.2 [пособия ИТМО](https://books.ifmo.ru/file/pdf/3031.pdf).
В принятой реализации mode 1 включает кнопку, mode 2 отключает.

## Архитектура и кооперативность

`main` обслуживает транспорт и консоль, читает SysTick и кнопку, обновляет
светофор и записывает светодиоды. На один вызов консоли приходится не более
16 входных символов. Пока нет входа или места в TX, приложение продолжает
обслуживать светофор. В режиме I отправка лишь помещает байты в очередь;
HAL `_IT`/собственный обработчик передают один байт, а TC завершает передачу.
В P приём не ждёт следующий символ. HAL передаёт один байт с ограниченным
тайм-аутом; регистровый драйвер проверяет TXE и возвращает управление.
Обычный цикл не содержит `HAL_Delay` и бесконечного ожидания периферии.
Остановка `fatal` используется только при неуспешной начальной настройке.

`traffic` не зависит от UART. Он получает события кнопки, хранит текущую фазу,
начало фазы, длительность красного, режим и запрос ускорения.
`command` строго распознаёт грамматику; число разбирается с проверкой границы
до умножения, поэтому значения за пределами uint32 не могут превратиться
в допустимый тайм-аут. Предел 86400 с ограничивает максимальную длительность
одними сутками. Разность unsigned ticks продолжает работать при переходе
счётчика через ноль. Зелёный, мигание и жёлтый не изменяются командой timeout.

## Общий драйвер очередей

RX и TX — кольцевые буферы с размером из макросов компиляции, без прикладной
логики. `serial_write` возвращает немедленно и принимает весь блок либо ничего.
Байт, передаваемый HAL по адресу, лежит в статическом `tx_byte`; указатель
не ссылается на стек. Флаг `busy` остаётся установленным до callback по TC.

TX-индексы изменяет только main; ISR сообщает окончание передачи. Копирование
большого TX-блока не запрещает прерывания. RX изменяют ISR и main, поэтому
чтение байта защищено коротким сохранением/восстановлением PRIMASK. Исходный
PRIMASK восстанавливается, а не безусловно разрешается. Снимок счётчиков также
читается под короткой защитой. API рассчитан на один main и один UART ISR,
не на несколько задач RTOS/одновременных производителей.

При переполнении или аппаратной ошибке RX увеличивается `rx_epoch`, очередь
очищается. Консоль отслеживает epoch и отбрасывает испорченную строку до Enter,
чтобы повреждённая команда не могла молча стать другой допустимой командой.
В TX переполнение означает отказ постановки; консоль заранее резервирует место
под эхо и максимальный ответ. Дребезг кнопки обрабатывается даже при mode 2.

## Смена режима во время обмена

Команда задаёт желаемый режим. Main ждёт пустой TX-очереди, отсутствия `busy`
и **TC**, после чего меняет источники IRQ и разрешение в NVIC. Это ожидание
через состояние, а не блокирующий цикл. Эхо самой команды успевает уйти в
старом режиме; `OK` приходит в новом. Принятые байты RX-очереди сохраняются.
Консоль приостанавливает разбор следующих команд до применения режима.

В HAL для отмены ожидания RX используется `HAL_UART_AbortReceive` без DMA:
он отключает источники RX и сбрасывает состояние handle, не ожидая символ.
Уже готовый байт читается опросом перед запуском нового приёма.
В собственном драйвере меняются CR1/CR3 и NVIC без сброса USART/DR.
В P RXNEIE, PEIE, TXEIE, TCIE, EIE и IRQ USART1 выключены; SysTick работает.

## Регистры USART1 и аппаратная разводка

| Регистр/бит | Назначение в этой реализации |
|---|---|
| RCC_APB2ENR.USART1EN | Разрешение тактирования USART1 |
| RCC_APB2RSTR.USART1RST | Начальный сброс собственной реализации |
| GPIOA MODER/AFR | PA9/PA10 в AF7 для USART1 TX/RX |
| BRR | Делитель скорости: round(16000000 / 57600) = 278, OVER8 = 0 |
| CR1 UE, TE, RE | Включение USART, передатчика, приёмника |
| CR1 M, PCE | Нулевые значения задают 8 бит без чётности |
| CR2 STOP | Ноль — один стоп-бит |
| CR3 RTSE/CTSE | Ноль — нет аппаратного управления потоком |
| SR RXNE | DR содержит полученный байт |
| SR TXE | Регистр передачи DR готов принять байт |
| SR TC | Последний кадр полностью передан, линия свободна |
| SR PE/FE/NE/ORE | Ошибки чётности/кадра/шума/переполнения |
| CR1 RXNEIE/PEIE/TXEIE/TCIE, CR3 EIE | Источники UART-прерываний |
| NVIC | Разрешение USART1 IRQ, приоритет 1; SysTick имеет приоритет 0 |

Чтение **SR, затем DR** снимает флаги ошибок; чтение DR снимает RXNE.
Писать `SR |= ...` для подтверждения приёма нельзя. TXE означает свободный DR,
но ещё не конец кадра — для переключения режима используется TC.
USART1 подключён к APB2, тактирование которого в проекте равно 16 МГц.
Вычисленный baud = 16000000 / 278 ≈ 57554 бит/с, ошибка делителя около −0,08%;
к ней добавляется погрешность HSI. Если менять часы, нужно обновить настройку
BRR в собственном драйвере, а в HAL — корректно обновлять дерево частот.

По [схеме производителя](SDK1.1M.pdf) DBG UART соединён с PA9/PA10 и PC6/PC7.
Используется только USART1 на PA9/PA10; PC6/PC7 остаются входами.
Контакты JTAG PA13/PA14/PA15/PB3/PB4 не перенастраиваются.

## Отличия от HAL/LL

HAL хранит handle, блокировки, отдельные RX/TX-состояния и счётчики, использует
callback-функции и поддерживает множество режимов, включая DMA.
`HAL_UART_Receive_IT` и `HAL_UART_Transmit_IT` запускают неблокирующие операции,
но сами не создают произвольные очереди приложения; кольцевые очереди добавлены
в общем драйвере. HAL polling RX с Timeout=0 возвращает HAL_TIMEOUT без ожидания,
если RXNE не установлен. Polling TX ограничен тайм-аутом, IRQ TX не ждёт кадр.

Собственный драйвер покрывает нужную конфигурацию USART1 57600 8N1 и управляет
регистрами напрямую. В ISR он принимает RX, пишет DR при TXE и завершает
операцию при TC. Универсальные DMA, LIN, multiprocessor, 9-битный формат и
автоматическая смена аппаратной частоты не заявляются. LL тоже является тонким
регистровым интерфейсом; отличие собственного решения — самостоятельно
написанный алгоритм, отсутствие HAL/LL UART и явно ограниченная конфигурация.
В регистровой сборке HAL остаётся для часов и SysTick, а UART HAL source
не компилируется скриптом. GPIO/CMSIS из ЛР 1 используются в обеих частях.

## Что показать на защите

1. Собрать HAL-версию, подключить терминал 57600 8N1, показать эхо и `?`.
2. Проверить `set mode 2`: кнопка не ускоряет красный; `set mode 1`: ускоряет.
3. Задать `set timeout 8`, показать красный 8 с и сокращение до 2 с.
4. Выполнить `set interrupts off`, затем `?`: получить P; повторить для on и I.
5. В отладчике показать `USART1->BRR`, CR1/CR3, `traffic`, `console`, `lab2_fault`.
6. Повторить на собственной сборке, объяснить разницу TXE/TC, работу SR→DR и NVIC.
7. Показать отказ для `set timeout 0`, отрицательного/слишком большого числа,
   длинной строки и восстановление после следующего Enter.

Проверять длительности без остановок отладчика. Эмуляционные проверки подтверждают
логику и MMIO-последовательности, но не работу USB/COM и электрическую связь стенда.
