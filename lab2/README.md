# Лабораторная 2 — UART и прерывания, вариант 1 «Светофор»

ЛР 2 продолжает ЛР 1 на стенде SDK-1.1MC.427: кнопка и светофор работают
кооперативно, а UART позволяет менять настройки и узнавать состояние.
Требования взяты из заметки «Лабораторная работа 2» в Obsidian и раздела 5.2
[пособия ИТМО](https://books.ifmo.ru/file/pdf/3031.pdf).

Первая часть: два режима драйвера на HAL — опрос и прерывания.
Вторая часть: отдельная сборка с собственным регистровым UART вместо HAL/LL UART.
Прикладной код и очереди одинаковы в обеих сборках.

## Подключение и запуск

1. Подключить питание стенда и **DBG USB**, BOOT0 оставить для загрузки из Flash.
2. У FT2232 два интерфейса: **Interface 0** используется JTAG/OpenOCD,
   **Interface 1** — виртуальным COM-портом UART. В Windows для Interface 0
   нужен WinUSB, для Interface 1 — драйвер FTDI VCP. Не заменять Interface 1
   драйвером WinUSB. Настройка JTAG описана в [ЛР 1](../lab1/README.md).
3. Собрать и прошить одну из двух версий, используя команды ниже.
4. Открыть COM-порт Interface 1 в PuTTY или другом терминале:
   **57600 бит/с, 8 бит, без чётности, 1 стоп-бит, без flow control**.
   Local echo отключить: стенд сам возвращает полученные символы.
   На Linux имя порта обычно `/dev/ttyUSB*`; выбрать именно канал UART FT2232.
5. После сброса светофор начинает с красного, кнопка включена (`mode 1`),
   красный длится 12 с, UART работает по прерываниям (`I`).

Схема [SDK1.1M.pdf](docs/SDK1.1M.pdf), страницы PDF 2–3:
USART1 TX = **PA9**, RX = **PA10**, AF7. Эти линии соединены также с PC6/PC7;
они оставлены входами, USART6 не включается. PB6/PB7 относятся к другому
разъёму, для DBG USB здесь не используются.
Светодиоды — PD13/PD14/PD15, кнопка — PC15 active-low, как в ЛР 1.
HSI, SYSCLK, APB1 и APB2 — 16 МГц, PLL выключен. BRR = 278 (`0x116`).

## Команды

Команда завершается Enter: принимаются CR, LF и CRLF. Максимум 63 символа
в строке. Регистр и пробелы значимы. Каждый принятый исправный символ возвращается
эхом; ответ начинается с CRLF и заканчивается CRLF. Пустая строка не выполняет
команду; Backspace и Delete убирают последний символ из буфера команды.

| Команда | Действие и ответ |
|---|---|
| `?` | Например: `red, mode 1, timeout 12, I` |
| `set mode 1` | Обрабатывать нажатия кнопки, ответ `OK` |
| `set mode 2` | Игнорировать кнопку и сбросить сохранённый запрос, ответ `OK` |
| `set timeout X` | Длительность красного в **секундах**, целое X от 1 до 86400, ответ `OK` |
| `set interrupts on` | Перейти на UART с прерываниями (`I`), затем ответить `OK` |
| `set interrupts off` | Перейти на опрос (`P`), затем ответить `OK` |
| Неизвестная команда или неверный аргумент | `ERROR: unsupported command or invalid argument` |

Статус цвета: `red`, `green`, `blinking green`, `yellow`. Во время мигания
ответ всегда `blinking green`, включая выключенный полупериод.

Тайм-аут меняет длительность текущей/последующей красной фазы, не перезапуская
отсчёт. Если новый порог уже достигнут, следующий оборот main сменит фазу.
Зелёный остаётся 3 с, мигание — 3 с с полупериодом 500 мс, жёлтый — 1 с.
Нажатие в режиме 1 сокращает красный до четверти заданного тайм-аута **от начала
красной фазы**, как в имеющейся реализации ЛР 1; на мигании/жёлтом запрос
сохраняется до следующего красного, на зелёном новое нажатие игнорируется.
Обработка дребезга продолжается в режиме 2, поэтому удержанная кнопка не становится
новым нажатием при возвращении в режим 1.

## Сборка и прошивка

Из корня `Computing-systems-labs`:

```bash
# Часть 1, HAL. Обе разновидности I/P находятся в одной прошивке.
python lab2/tools/build.py
python lab2/tools/board.py flash --elf lab2/build/lab2_hal.elf

# Часть 2, собственный регистровый UART. Те же команды и переключение I/P.
python lab2/tools/build.py --backend register
python lab2/tools/board.py flash --elf lab2/build/lab2_register.elf
```

Скрипт сборки находит `arm-none-eabi-gcc` в PATH, в `ARM_GCC_BIN` или в CubeIDE
под `C:/ST`. Для OpenOCD при необходимости задать `OPENOCD_EXE` и
`OPENOCD_SCRIPTS` — каталог, содержащий `target/stm32f4x.cfg`.
Программирование использует [SDK11M.cfg](SDK11M.cfg), **FT2232/JTAG**, не ST-LINK.
`probe` проверяет доступ к контроллеру, `debug` запускает сервер GDB на порту 3333.
Физическая работа стенда и COM-порта пока не подтверждена.

В **STM32CubeIDE** импортировать каталог `lab2` как Existing Project без копирования.
По умолчанию Debug/Release собирают HAL-версию в `Debug/lab2.elf` или
`Release/lab2.elf`. Для собственной версии добавить символ
`UART_REGISTER_BACKEND` в настройки C Compiler → Preprocessor и сделать Clean/Build.
Не подключать UART из CubeMX: `.ioc` отсутствует, инициализация выполнена вручную.
Отладчик настроить на пользовательский OpenOCD/JTAG config `SDK11M.cfg`,
либо подключиться через GDB Hardware Debugging к отдельно запущенному серверу.

## Очереди и ограничения

`SERIAL_RX_CAPACITY` (128 байт) и `SERIAL_TX_CAPACITY` (512 байт) задаются
при компиляции в `serial.h` либо через `-D`. Общий драйвер не знает о светофоре
и командах; только клиент консоли требует TX не менее 96 байт для целого ответа.
Запись принимает весь блок либо возвращает `false`, если места недостаточно.
Консоль приостанавливает разбор входа, когда не может вместить эхо и ответ.

Переключение I/P — отложенное: main продолжает работу и ждёт опустошения TX
и флага TC. Ответ `OK` передаётся уже в новом режиме; RX-очередь сохраняется.
В I вызовы приёма/отправки не ждут линию, используются HAL `_IT` или USART1 ISR.
В P приём возвращает сразу; HAL-передача одного байта имеет тайм-аут 2 мс
(проверка HAL выполняется по миллисекундным тикам). Собственная передача в P
лишь проверяет TXE и пишет DR. SysTick остаётся разрешён в обоих режимах.

Конечные очереди не могут гарантировать приём неограниченного потока без
flow control. При RX overflow или PE/FE/NE/ORE очередь входа очищается,
счётчик диагностики растёт, а текущая строка отвергается до следующего Enter.
Сообщение: `ERROR: input lost or line too long; repeat command`.
Перед следующей командой дождаться ответа, особенно в P.

## Тесты

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r lab2/tests/requirements.txt
python lab2/tools/build.py
python lab2/tools/build.py --backend register
python lab2/tools/build.py --test
python lab2/tools/build.py --test --backend register
python lab2/tests/run_tests.py
```

Unicorn исполняет скомпилированный C для Cortex-M4, включая настоящий HAL UART
и собственный драйвер. Модель MMIO воспроизводит RXNE/TXE/TC, SR→DR,
включение IRQ в NVIC и побочный эффект GPIO BSRR. Она вызывает настоящий ISR
между итерациями приложения; электрические уровни, USB и точное время аппаратных
прерываний не моделируются. Это проверка прошивки, а не сдача симулятора части 2.
Результаты и ручной сценарий: [VALIDATION.md](docs/VALIDATION.md).

## Основные файлы

- `Core/Src/main.c` — часы, светодиоды, кнопка, UART и кооперативный цикл.
- `serial.c/.h` — очереди, обратное давление и переключение I/P.
- `uart_hal.c` — HAL UART для первой части, два режима работы.
- `uart_register.c` — собственная реализация UART для второй части.
- `uart_pins.c` — AF7 на PA9/PA10, освобождение общих линий PC6/PC7.
- `console.c/.h`, `command.c/.h` — эхо, строки, проверка и выполнение команд.
- `traffic.c/.h` — автомат светофора с настраиваемым красным и режимом кнопки.
- `button`, `led`, `gpio_driver` — модули из ЛР 1.

Архитектура, регистры и отличие от HAL/LL: [DEFENSE.md](docs/DEFENSE.md).
Сторонние компоненты и лицензии: [THIRD_PARTY.md](docs/THIRD_PARTY.md).
