# Лабораторная 4 — I²C и матричная клавиатура, задание 1

Самостоятельный проект STM32CubeIDE для **SDK-1.1MC.427 / STM32F427**.
Назначенный номер **6** соответствует подтверждённому заданию **1**:
музыкальная клавиатура из ЛР 3 с вводом от кнопок стенда.
Основа — заметка Obsidian «Лабораторная работа 4», разделы 1.6–1.7 и 5.4
[пособия SDK-1.1M, редакция 23.09.2026](https://docs.yandex.ru/docs/view?url=ya-disk-public%3A%2F%2FgnZjE%2B0%2BtAOnWD%2BQF6x%2FKHumUuwVPt0puaIMSPgwP2pdqinF8TVHBZsJz%2BlCybhSq%2FJ6bpmRyOJonT3VoXnDag%3D%3D&name=SDK-1.1M_26092301.pdf&nosw=1).
Условие ЛР 4 — печатные страницы **86–87**, страницы PDF **87–88**;
в заголовке пособия сохранена пометка «задание уточняется».

## Подключение и первый запуск

1. Подключить питание и **DBG USB**, выбрать загрузку из Flash через BOOT0.
2. **Замкнуть SA2.7** для соединения PA5 с усилителем и звукоизлучателем BA1.
   Для встроенной клавиатуры дополнительные замыкания SA2.1–SA2.6 не нужны.
3. Собрать и прошить программу командами ниже.
4. Открыть UART-канал FT2232: **57600 бит/с, 8N1, без flow control**,
   local echo выключен. UART служит для вывода; ввод из терминала игнорируется.
5. После сброса выбран режим **TEST**, звук выключен. Отпустить все кнопки;
   нажать SB1 — терминал должен показать `Key 1`. Удержание не повторяет код.
6. Боковой кнопкой **PC15** перейти в **PIANO**, затем играть SB1–SB7.

FT2232 **Interface 0** используется для OpenOCD/JTAG, **Interface 1** — COM-порт.
В Windows WinUSB нужен только Interface 0; Interface 1 использует FTDI VCP.

Подключение проверено по [электрической схеме SDK-1.1M](docs/SDK1.1M.pdf):

| Узел | Подключение |
|---|---|
| Звук | PA5, AF1, TIM2_CH1 → SA2.7 → усилитель → BA1 |
| UART | USART1, PA9/PA10, AF7; PC6/PC7 оставлены входами |
| I²C | I2C1, PB8=SCL, PB9=SDA, AF4, open-drain |
| Буфер шины | PD7=1 включает PCA9517; это не RESET расширителя |
| Клавиатура | DD12, PCA9538PW, **семибитный адрес 0x71**; DD10 с 0x70 не используется |
| Строки / столбцы | P0–P3 / P4–P6 расширителя; P7 не используется |

## Режимы и управление

Нажатие PC15 переключает TEST ↔ PIANO после подавления дребезга **30 мс**.
Переключение сообщается в UART, останавливает текущую ноту/гамму и сохраняет
октаву с длительностью. После него матрица должна быть полностью отпущена
не менее 30 мс: удерживаемая кнопка не становится нажатием в новом режиме.

| Кнопка / код в TEST | Действие в PIANO | Эквивалент ЛР 3 |
|---|---|---|
| SB1–SB7 / 1–7 | До, ре, ми, фа, соль, ля, си | `1`–`7` |
| SB8 / 8 | Октава выше | `+` |
| SB9 / 9 | Октава ниже | `-` |
| SB10 / 10 | Длительность +0,1 с | `A` |
| SB11 / 11 | Длительность −0,1 с | `a` |
| SB12 / 12 | Семь нот гаммы подряд, без заданных пауз | Enter |

Исходные настройки: первая октава **5/9**, длительность **1,0 с**.
Диапазоны: девять октав от субконтроктавы до пятой, длительность **0,1–5,0 с**.
На границе выводится `LIMIT`, настройка сохраняется. Новая нота или SB12
заменяет текущее воспроизведение. Изменение настроек действует на следующий
запуск; активная нота и вся гамма сохраняют исходную октаву и длительность.
UART сообщает коды в TEST, ноты с частотой/длительностью и настройки в PIANO.

Физическая нумерация идёт по столбцам, как обозначения SB на схеме:

| Выбранная строка | P4 | P5 | P6 |
|---|---|---|---|
| P0 | SB1 | SB5 | SB9 |
| P1 | SB2 | SB6 | SB10 |
| P2 | SB3 | SB7 | SB11 |
| P3 | SB4 | SB8 | SB12 |

## Опрос и архитектура

`i2c_bus` выполняет обмены регистрами без ожидания флагов в цикле;
`keypad` собирает четыре строки в 12-битную маску и фильтрует её.
`app` переключает режимы и передаёт события автомату `piano`, а `sound`
формирует аппаратный PWM. UART с прерываниями и GPIO-драйвер унаследованы из ЛР 2.

Инициализация DD12: Configuration=0xFF, Output=0x00, Polarity=0x00.
Выбранная строка становится выходом с нулём; остальные остаются входами,
затем после 1 мс читаются активные низким уровнем столбцы. Дребезг — 30 мс
по полным кадрам. Нажатие выдаётся до отпускания, удержание не повторяется;
несколько кнопок, смена кнопки без устойчивого отпускания и ошибка обмена
блокируют ввод до подтверждённого отпускания всех кнопок.

Ядро работает на **120 МГц**, APB1=30 МГц, APB2=60 МГц, TIM2CLK=60 МГц.
I²C настроен на 80 кГц: CCR=188 даёт номинально **79,787 кГц**, TRISE=31.
Частота выбрана с учётом ограничения repeated START в Standard-mode
88–100 кГц: [ES0206, §2.10.4](https://www.st.com/resource/en/errata_sheet/es0206-stm32f427437-and-stm32f429439-device-errata-stmicroelectronics.pdf).
Формулы, транзакции и вопросы для защиты: [DEFENSE.md](docs/DEFENSE.md).

## Сборка, прошивка и проверки

Из корня репозитория; в Windows можно использовать `python` вместо `python3`:

```bash
python3 lab4/tools/build.py
python3 lab4/tools/board.py flash
python3 lab4/tools/build.py --test
python3 lab4/tests/run_tests.py
```

Нужны Python 3 и `arm-none-eabi-gcc` в PATH либо каталог toolchain в `ARM_GCC_BIN`.
Для тестов: `python3 -m pip install -r lab4/tests/requirements.txt`
(рекомендуется отдельное venv). Сборка создаёт `lab4/build/lab4.elf` и `.bin`.
Для прошивки задать `OPENOCD_EXE` и `OPENOCD_SCRIPTS` — каталог с
`target/stm32f4x.cfg`; используется локальный `SDK11M.cfg`, **FT2232/JTAG**.
Команды `board.py probe` и `board.py debug` проверяют подключение и запускают GDB-сервер.

В CubeIDE импортировать `lab4` как **Existing Project**, без копирования.
Debug/Release создают `Debug/lab4.elf` / `Release/lab4.elf`; например:
`python3 lab4/tools/board.py flash --elf lab4/Debug/lab4.elf`.
Для отладки выбрать пользовательский OpenOCD/JTAG config `SDK11M.cfg`.
CubeMX и `.ioc` не требуются. Результаты тестов: [VALIDATION.md](docs/VALIDATION.md).

## Ограничения и диагностика

Очередь отчётов содержит **16 событий**, TX UART — **512 байт**. Если вывод
отстаёт, звук и опрос продолжаются; новые отчёты при заполнении отбрасываются
и учитываются в `app.dropped_reports`. Счётчики I²C доступны через
`i2c_bus_stats()`, кадров/ошибок/событий клавиатуры — через `keypad_stats()`.

Тайм-аут транзакции I²C — **10 мс**. После сбоя драйвер до 2 мс ждёт STOP;
если шина занята, выполняет bus clear: девять импульсов SCL через GPIO
open-drain и STOP, затем возвращает AF4 и переинициализирует I2C1.
Восстановление ограничено **30 мс**, повтор инициализации DD12 начинается
через **50 мс** после завершения неудачного обмена. Кадр отбрасывается.
Постоянное внешнее замыкание SDA/SCL может сохраняться; главный цикл продолжает работу.
Одиночный BERR очищается без прерывания обмена по
[ES0206, §2.10.1](https://www.st.com/resource/en/errata_sheet/es0206-stm32f427437-and-stm32f429439-device-errata-stmicroelectronics.pdf#page=25).
Аппаратный запуск, USB/COM, звук и точность HSI на стенде пока не проверены.
Лицензии и происхождение кода: [THIRD_PARTY.md](docs/THIRD_PARTY.md).
